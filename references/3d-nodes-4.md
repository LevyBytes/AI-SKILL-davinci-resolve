# 3D Nodes (part 4)

> Davinci Resolve reference. Original prose; identifiers preserved verbatim.

The job of the Locator 3D node is to convert a point sitting in 3D space into 2D coordinates that other nodes can feed into expressions or modifiers. Hand the Locator a camera plus the output image's dimensions, and it maps a 3D control's coordinates into 2D screen space. That 2D position surfaces as a numeric output you can wire to or from other nodes. For instance, to tie an ellipse's center to the Locator's 2D position, right-click the Mask center control and pick Connect To > Locator 3D > Position.

### Inputs

A pair of inputs take 3D scenes as their sources. The orange scene input is mandatory, whereas the green Target input is optional. SceneInput: The mandatory orange scene input takes a 3D scene's output. That scene ought to hold the object or point in 3D space you mean to convert into 2D coordinates. Target: The optional green target input takes a 3D scene's output. Supply one and the scene's transform center fixes the Locator's position, after which the Locator's transformation controls act as offsets from that position.

### Basic Node Setup

Whatever scene you feed the Locator’s input has to include the camera that the coordinates get projected through. The recommended practice, then, is to position the Locator downstream of the Merge that brings the camera into the scene. Wire an object into the Locator node’s target input and the Locator parks itself at that object’s center, while the Transformation tab’s translation XYZ sliders operate in the object’s local coordinate space rather than global scene space. That comes in handy for following an object’s position even as extra transformations get applied further down the chain.

### Merge 3D [3Mg]

### The Merge 3D node

### Merge 3D Introduction

Within Fusion, the Merge 3D node is the chief node for bringing distinct 3D elements together into one shared 3D environment. Take a scene built from an image plane, a camera, and a light: the camera can't see the image plane and the light won't touch it until all three are gathered into the same environment via the Merge 3D node. The Merge carries the usual transformation controls present on most nodes in Fusion’s 3D suite. What sets it apart is that altering the Merge's translation, rotation, or scale ripples through to every object wired into the Merge. That very behavior underpins all parenting inside Fusion’s 3D environment.

### Inputs

At first the Merge node shows just two inputs, but each time you connect one a fresh input pops up on the node, guaranteeing one is always open for adding another element to the scene. SceneInput[#]: You use these multicolored inputs to attach image planes, 3D cameras, lights, complete 3D scenes, and other Merge 3D nodes too. The node accepts an unlimited number of inputs, sprouting more on the fly as required so that at least one input remains free for connection.

### Basic Node Setup

A Merge 3D sits at the center of any 3D composite, with every element of a 3D scene feeding into it. You can chain several Merge 3D nodes together to manage lighting or simply to keep things tidier. The final Merge 3D in such a chain has to attach to a Renderer 3D before it can come out as a 2D image.

A Merge 3D wired to an Image Plane, an FBX Mesh object, a SpotLight, and a camera Inspector

### Merge 3D controls

### Controls Tab

The Controls tab serves a single purpose: passing through whatever lights are wired to the Merge 3D node. Pass Through Lights Tick the Pass Through Lights checkbox and lights travel through the Merge into its output to influence downstream elements. By default, lights aren't forwarded downstream to reach the rest of the scene. This is commonly used to keep projections from landing on geometry brought in later in the scene.

### Override 3D [3Ov]

### The Override 3D node

### Override 3D Node Introduction

With the Override node you can alter object-specific options for every object in a 3D scene all at once. It helps, say, when you want each object in the input scene to render as a wireframe. On top of that, for 3D particle systems and the Text 3D node, this node is your only route to setting the wireframe, visibility, lighting, matte, and ID options.

### Inputs

SceneInput: The orange Scene input takes the output from a Merge 3D node or from any node that builds a 3D scene.

### Point Cloud 3D [3PC]

### The PointCloud 3D node

### Point Cloud 3D Node Introduction

Typically a Point Cloud amounts to a host of null objects spawned by 3D tracking or modeling software. Coming from 3D tracking software, the points usually stand for each of the patterns that were tracked to build the 3D camera path. Such point clouds help you pin down a ground plane and line up other 3D elements with the tracked image. The Point Cloud 3D node builds a point cloud either by importing a file out of a 3D tracking application or by generating one when you run the Camera Tracker node. NOTE: A null object is an unseen 3D object carrying every one of the same transform properties a visible 3D object has.

### Inputs

The Point Cloud carries just one input, meant for a 3D scene. SceneInput: This orange input takes a 3D scene.

### Basic Node Setup

You view and wire up the Point Cloud 3D node by way of a Merge 3D node, which folds it into the broader 3D scene.

### Onscreen Contextual Menu

Often, one or more points within an imported point cloud get hand-assigned to follow the position of a particular feature. Such points generally bear names that set them apart from the cloud's other points. To check a point's present name, rest the mouse pointer right on top of it, and shortly a little tooltip surfaces showing the point's name. Selecting the Point Cloud 3D node tacks a submenu onto the viewer’s contextual menu carrying several options that make it easy to find, rename, and pull these points away from the rest of the point cloud.

### The Point Cloud 3D contextual menu options

These are the options the contextual menu offers: Find: Choosing this from the viewer contextual menu brings up a dialog for searching out and selecting a point by name, and every point matching the pattern gets selected. Rename: Rename any point by choosing Rename from the contextual menu. Enter the new name in the dialog that appears and press Return. The point then takes that name with a four-digit number appended. As an example, the Name window is window0000, so multiple points read window0000, window0001, and onward. A name has to be a valid Fusion identifier (meaning no spaces, and it can't begin with a number). Delete: Choosing this removes whatever points are currently selected. Publish: By default, a cloud point's precise position stays hidden. To reveal it, select the points and then pick the Publish option from this contextual menu. Doing so adds a coordinate control to the control panel for each published point, showing that point’s current location.

### Projector 3D [3Pj]

### The Projector 3D node

### Projector 3D Node Introduction

You use the Projector 3D node to cast an image onto 3D geometry. There are plenty of uses for this: layering multiple textures onto objects, spreading one texture over several separate objects, casting background plates from the camera’s vantage point, image-based rendering tricks, and beyond. The Projector node is merely one among several nodes able to cast images and textures, each method bringing its own pros and cons. For further reading, turn to Chapter 85, “3D Compositing Basics,” within the DaVinci Resolve Reference Manual, or else Chapter 25 of the Fusion Reference Manual. You can let projected textures “slide“ across the object whenever the object shifts relative to the Projector 3D, or instead bundle the two inside a Merge 3D so they travel together and the texture stays pinned to the object. Grasping what the Projector 3D node can and can't do comes easiest if you treat the Projector as a flavor of the SpotLight node. Because the Projector 3D node is in truth a light, several notable things follow when it runs in Light or Ambient Light projection mode:

- Lighting has to be switched on before the projection's results show up.
- The light the projector throws counts as diffuse/specular light. That means it's

swayed by the surface normals and can generate specular highlights. If you'd rather avoid that, set the Projector 3D to project into the Ambient Light channel.

- Switching on Shadows makes Projector 3D cast shadows.
- As with any other light, the light a Projector 3D emits reaches only objects feeding into the first Merge 3D that lies downstream of the Projector 3D node in the node tree.
- Turning on the Merge 3D’s Pass Through Lights checkbox lets the projection illuminate objects further downstream.
- The light a Projector 3D emits is steered by the Lighting options settings on objects together with the Receives Lighting options on materials.
- In Light or Ambient Light mode, Alpha values within the projected image don't clip geometry. Reach for Texture mode instead.
- When two projections overlap, their light contributions sum together.

To cast re-lightable textures or textures for non-diffuse color channels (Specular Intensity or Bump, say), turn to the Texture projection mode instead:

- A projection in Texture mode lands only on objects that use the Catcher node's output for some or all of the material applied to that object.
- A Texture mode projection clips the geometry by the Alpha channel of the projected image.

Consult the section covering the Catcher node for more detail.

### Camera Projection vs. Projection 3D Node

The Camera 3D node offers a projection feature too, and it's the one to reach for when the projection should match a camera, since this node grants more say over aperture, film back, and clip planes. The Projector 3D node, on the other hand, was built to serve as a custom light in 3D scenes for layering and texturing, giving you finer control over light intensity, color, decay, and shadows.

### Inputs

The Projector 3D carries two inputs: one for the scene you're casting onto and one for the image being cast. SceneInput: The orange scene input takes a 3D scene. Wire a scene here and transformations applied to the spotlight ripple through to the rest of the scene as well. ProjectiveImage: The white input anticipates a 2D image to drive the projection. This connection is mandatory.

Enabled With this checkbox on, the projector acts on the scene; clear it to switch the projector off. It's not the same thing as the red switch at the Inspector's upper-left corner. That red switch shuts the tool down entirely and hands the image along untouched, whereas the Enabled checkbox covers only the effect portion of the tool. Other parts, such as scripts in the Settings tab, keep processing as usual. Color The input image gets multiplied by this color ahead of being cast into the scene. Intensity This slider sets the projection's Intensity while the Light and Ambient Light projection modes are in use. Under Texture mode, the option scales the texture's Color values once they've been multiplied by the color. Decay Type A projector starts out at No Falloff, so its light hits geometry with the same intensity no matter how far the geometry sits from the projector. To make the intensity drop off over distance, switch the Decay type to either Linear or Quadratic modes. Angle The node's Cone Angle is the breadth of the cone within which the projector puts out its full intensity. A larger angle widens the cone angle, up to a ceiling of 90 degrees. Fit Method The Fit Method decides how the projection is fitted inside the projection cone.

The first point to grasp is that even though this documentation might say “cone,” the Projector 3D and Camera 3D nodes don't actually cast a cone; what they cast is closer to a pyramid of light whose apex sits at the camera/projector. The Projector 3D node forever casts a square pyramid of light—that is, its X and Y angles of view match. The Camera 3D node's pyramid of light can come out non‑square according to how the camera's Film Back is set. The aspect of the image wired into the Projector 3D/Camera 3D doesn't shift the pyramid's X/Y angles; rather, the image is scaled to fit the pyramid per the fit options. Whenever the pyramid's aspect (AovY/AovX) and the image's aspect (height _ pixelAspectY)/ (width _ pixelAspectX) coincide, the fit options aren't needed and they all behave identically. But once the image's aspect and the pyramid's (as governed by the Film Back settings in Camera 3D) differ, the fit options start to matter. Fit by Width, for one, fits the image's width across the width of the Camera 3D pyramid; here, if the image has a larger aspect ratio than the pyramid does, part of the projection spills vertically past the pyramid. Five options exist:

- Inside: The image is scaled uniformly so its largest dimension just fits inside the cone. Put another way, it scales the image as large as it can while keeping the image entirely inside the pyramid of light. The upshot is that nothing beyond the pyramid of light ever catches any projected light.
- Width: The image is scaled uniformly so its width fits inside the cone. Mind that the image may still spill past the cone along its height.
- Height: The image is scaled uniformly so its height fits inside the cone. Mind that the image may still spill past the cone along its width.
- Outside: The image is scaled uniformly so its smallest dimension just fits inside the cone. Put another way, it scales the image as small as it can while still covering the whole pyramid (so the pyramid sits entirely within the image). The upshot is that every pixel of every object inside the pyramid of light is always lit.
- Stretch: The image is scaled non-uniformly so it covers the projector's cone exactly.

### Projection Mode

- Light: Casts the texture as a diffuse/specular light.
- Ambient Light: Draws on an ambient light to drive the projection.
- Texture: Paired with the Catcher node, this mode enables re-lightable texture projections. The projection lands solely on objects that include the catcher material among their material shaders. A handy trick is to wire a Catcher node into the Specular Texture input on a 3D Material node (a Blinn, for example), which makes every object using the Blinn material take the projection as part of its specular highlight. You can apply this approach at any material input that accepts texture maps, including the Specular and Reflection maps.

Shadows Because the projector builds on a spotlight, it can likewise cast shadows by means of shadow maps. The controls revealed here set the shadow map's size and behavior.
