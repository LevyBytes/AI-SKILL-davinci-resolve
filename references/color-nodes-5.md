### Hue Curves [HCv]

### The Hue Curves node

### Hue Curves Node Introduction

With the Hue Curves node you reshape an image’s color through a family of spline curves. There are splines for steering the image’s hue, saturation, and luminance, plus one for each separate color channel. A further group of curves lets you apply suppression channel by channel. What sets the Hue Curves node apart from Fusion’s other color correction nodes is how far the splines can be pushed: you can clamp the node’s reach down to a tiny slice of the image or stretch it across a broad swath. On top of that, the curves can be keyframed so they track how the image evolves frame to frame. Because the spline’s main axis follows the image’s hue, pulling out one particular color for tweaking becomes far simpler.

### Inputs

Two inputs sit on the Hue Curves node: one carries the primary image, and the other takes an effect mask that confines where the color correction lands. Input: Orange in color, this is the sole mandatory hookup, feeding a 2D image into the Hue Curves color correction. Effect Mask: This optional blue input takes a mask shape built from polylines, simple primitive shapes, paint strokes, or bitmaps generated by other tools. Wiring a mask here restricts the Hue Curves operation to the pixels the mask covers. The effect mask gets applied once the tool has finished its processing.

### Basic Node Setup

As is true of many 2D image-processing nodes, the Hue Curves node takes in a 2D image — supplied here by a Loader node or the MediaIn1 pictured below. From there its output carries on down the node tree into a further 2D image-processing node or a Merge node.

### Controls Tab

A row of color attribute checkboxes on the Controls tab governs which splines appear inside the Spline window. That spline graph stretches sideways, with control points seated at each primary color along the horizontal. Dragging those control points alters whichever color attribute you have chosen. Mode The Mode setting flips between No Animation and Animated Points. By default it sits on No Animation, in which your curve edits hold steady across the whole clip. Switch the Mode over to Animated Points or Dissolve and the color curve can then change across time. Dissolve has effectively been retired and remains only so older comps still open. Color Channel Checkboxes These boxes mark which splines you can edit and which ones respond when you sample a color with the Eyedropper. You may edit several active splines at once, yet it is usually tidier to keep only the spline you are working on active so the others stay untouched. Click the Eyedropper icon and a point lands on every active spline to mark the color you grabbed. Spline Window Acting as the central interface piece of the Hue Curves node, this graph display holds all the splines. It looks much like the Color Curves node, except here hue runs along the horizontal axis while the amount of adjustment runs up the vertical. Curves for the separate channels appear in the Spline window, which behaves as a compact Spline Editor — indeed, the very curves drawn here turn up and stay editable inside the full Spline Editor too. Every component’s spline starts out flat, its control points lined up across the primary colors, which read from left to right as Red, Yellow, Green, Cyan, Blue, and Magenta. Since the hue gradient wraps around in a cycle, each curve’s leftmost control point ties back to its rightmost one. A right-click within the graph pops a contextual menu offering choices to reset curves, bring in external curves, tune the smoothness of the chosen control points, and more.

In and Out Reach for the In and Out controls when you need to dial in exact figures for a chosen point. To revise a value, highlight a point and type the In/Out figures you want. Eyedropper Press and drag from the Eyedropper icon and your pointer turns into an Eyedropper. Keep the button held while you sweep over a viewer to sample a pixel out of whatever image is shown. ### OCIO CDL Transform [OCT]

### The OCIO CDL Transform node

### OCIO CDL Transform Node Introduction

Three OCIO nodes are how Fusion plugs into the Open Color IO color management workflow.

- With the OCIO CDL Transform node you can build, store, retrieve, and lay down a Color Decision List (CDL) grade.
- The OCIO Color Space handles advanced color space conversions, driven by an OCIO config file.
- The OCIO File Transform lets you bring in and apply an assortment of Lookup tables (LUTs).

As a rule, the OCIO color pipeline is built up out of a collection of color transformations spelled out in OCIO-specific config files, which usually carry a “.ocio” extension. Such config files give you a way to pass color settings around inside a facility or across several. Which config file gets loaded is ordinarily pointed to by a user-created environment variable named “OCIO,” although certain tools let you override that. Should no other \*.ocio config files turn up, the system falls back on the DefaultConfig.ocio file in Fusion’s LUTs directory.

To dig into how the format works under the hood, consult the official pages over at opencolorio.org.

### Inputs

There are two inputs on the OCIO CDL Transform node: one for the primary image and one for an effect mask that bounds the region in which the CDL takes effect. Input: The orange input is the only connection you must make, feeding a 2D image output into the CDL grade. Effect Mask: This optional blue input accepts a mask shape made from polylines, simple primitive shapes, paint strokes, or bitmaps coming out of other tools. Hook a mask up here and the CDL grade is held to just the pixels inside the mask. That effect mask takes effect after the tool has run its processing.

### Basic Node Setup

You will commonly drop the OCIO CDL Transform node downstream of a Gamut node that has already taken the Loader into linear color inside Fusion Studio.

An OCIO CDL Transform node sitting on a Loader node, once a Gamut conversion has brought it to linear within Fusion Studio Inspector

### OCIO Transform controls

### Controls Tab

On the OCIO CDL Transform, the Controls tab holds primary grading color correction controls laid out in a CDL-friendly format. R, G, B tweaks are driven by Slope, Offset, and Power, and there is a global Saturation control as well. This same tab also lets you bring CDL-compatible adjustments in and send them back out. Operation The menu flips between File and Controls. Pick File mode to load standard ASC-CDL files; pick Controls mode to set Slope, Offset, Power, and Saturation by hand and to write out the CDL file. NOTE: In DaVinci Resolve terms, slope behaves much like gain, steering the mids-to-high contrast. Offset shifts the whole color balance and exposure, and Power resembles contrast pivoting on a raised point, handing you command over shadow contrast. Direction Flips between Forward and Reverse. Forward lays down the corrections set in the node; Reverse attempts to back them out. Bear in mind that some color corrections simply cannot be reversed — picture every slope value driven to 0.0, which yields a wholly black image. Undoing that is impossible, in math and on screen alike.

### Slope

### Offset

Multiplying the color values, Slope does the very thing that Gain does over in the Brightness Contrast node.

Offset adds onto the color values, matching what Brightness does within the Brightness Contrast node. Power Lays a Gamma Curve over the image, working as the inverse of the Gamma function found in the Brightness Contrast node.

Saturation Raises or lowers the color saturation, operating exactly as Saturation does in the Brightness Contrast node. Export File Lets you write the current settings out to a CDL file.

### OCIO Color Space [OCS]

### The OCIO Color Space node

### OCIO Color Space Node Introduction

Fusion taps the Open Color IO color management workflow through a trio of OCIO nodes.

- The OCIO CDL Transform node lets you author, save off, bring back, and apply a Color Decision List (CDL) grade.
- Sophisticated conversions between color spaces, governed by an OCIO config file, come from the OCIO Color Space.
- Loading and applying a range of Lookup tables (LUTs) is the job of the OCIO File Transform.

For the most part, the OCIO color pipeline takes shape from a group of color transformations laid out in OCIO-specific config files, typically bearing a “.ocio” extension. These config files exist so color settings can travel within one facility or among many. Normally a user-created environment variable named “OCIO” points at whichever config file should load, though a handful of tools permit overriding that. When no other \*.ocio config files can be found, the DefaultConfig.ocio file in Fusion’s LUTs directory steps in. Anyone wanting a thorough account of the format’s inner workings should look to the official opencolorio.org pages. You can grab example configs at https://opencolorio.readthedocs.io/en/latest/ configurations/\_index.html#configurations What the OCIO Color Space node does can equally be had through a View LUT node reached from the View LUT menu.

### Inputs

The OCIO Color Space node carries two inputs: one for the primary image and another for an effect mask that pins down where the color space conversion happens. Input: Colored orange, this is the lone required hookup, supplying a 2D image to the color space conversion. Effect Mask: This optional blue input takes a mask shape drawn from polylines, basic primitive shapes, paint strokes, or bitmaps produced elsewhere. Attach a mask here and the color space conversion is limited to the pixels under that mask. The effect mask is applied once the tool has done its work.

### Basic Node Setup

As a rule the OCIO Color Space node goes right behind a MediaIn node in DaVinci Resolve, or behind a Loader node in Fusion Studio. A companion OCIO Color Space node then sits immediately ahead of a Media Out node in DaVinci Resolve, or ahead of a Saver node in Fusion Studio.

### The OCIO File Transform node

### OCIO File Transform Node Introduction

By means of three OCIO nodes, Fusion hooks into the Open Color IO color management workflow.

- Use the OCIO CDL Transform node to make, keep, reload, and put down a Color Decision List (CDL) grade.
- The OCIO Color Space carries out refined color space conversions according to an OCIO config file.

### Set Canvas Color [SCv]

### The Set Canvas Color node

### Set Canvas Color Node Introduction

You reach for Set Canvas Color to assign a color to the region beyond the domain of definition (DoD). Normally that is the workspace stretching past the raster, and it stays unseen because anything outside the raster goes unrendered. The DoD can also fall inside the raster, though — something that crops up when you composite images smaller than the raster, or apply transforms. The default canvas color is black with no Alpha (transparent). Yet because certain nodes will alter an image’s canvas color — inverting a mask, for instance, flips the mask’s canvas from black to white — Set Canvas Color hands you control to make the canvas any color you need. So the Set Canvas Color node assigns the color of the workspace lying outside the domain of definition (DOD). Build a circular gradient, say, and the DoD becomes a square framing that gradient in the viewer. Whatever sits beyond the DoD is taken as black and thus skips rendering. To recolor the region past the DoD, hook the Set Canvas Color node up after the background and pick a new color. NOTE: Hover the pointer over a black region outside the raster and the RGB canvas color shows in the status bar down at the lower left of the Fusion window.

### Inputs

The Set Canvas Color node carries a pair of inputs — the first for your primary image, the next for a foreground. Input: Colored orange, this is the only connection you must make, taking a 2D image that exposes the canvas color whenever the image’s DoD comes up smaller than the raster. Foreground: The optional green foreground input lets the canvas color be sampled from whatever image you wire into it.

### Basic Node Setup

You position the Set Canvas Color node downstream of the transform that exposes a slice of the raster beyond the domain of definition.

A Set Canvas Color node placed on a transformed MediaIn 1 node Here the footage out of MediaIn1 has been scaled down with the Transform1 node, which leaves blank space surrounding the image inside the frame. Route that output through the SetCanvasColor node and you can recolor the blank space that rings the frame.

### White Balance [WB]

### The White Balance node

### White Balance Node Introduction

Turn to the White Balance node to clear out color casts automatically — the kind that arise from a camera being set up wrong or from poor lighting. You correct them either by dialing in a color temperature or by sampling a neutral color out of the original image where the cast shows. IMPORTANT: While sampling neutral colors with the Custom method, be certain you draw from the source image rather than from what the White Balance node outputs. That keeps the image steady as you sample, and it lets the White Balance node read the true original colors it has to fix.
