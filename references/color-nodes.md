# Color Nodes (part 1)

> Davinci Resolve reference. Original prose; identifiers preserved verbatim.

### Color Nodes

The Color nodes found in Fusion are covered throughout this chapter. Each node name has an abbreviation beside it that you can type into the Select Tool dialog while looking for tools, and that also serves in scripting references. Throughout this document, treat node trees that display MediaIn nodes in DaVinci Resolve as equivalent to Loader nodes in Fusion Studio, except where a difference is called out.

### ColorFX

One of the Color tool subcategories in Fusion, providing entry to an assortment of color processing tools.

### ACESTransform [ATr]

### The ACES Transform node

### ACES Transform Node Introduction

A straightforward node that lets you run color transforms by way of the ACES Input Device Transform and ACES Output Device Transform parameters.

### Inputs

There are two inputs on the ACES Transform node, namely the input plus the effect mask. Input: The orange input carries the main 2D image used for the auto gain. Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. Wiring a mask here confines the change to only the pixels falling inside that mask. The effect mask gets applied once the tool itself has finished processing.

### Basic Node Setup

Much like numerous other 2D image-processing nodes, the ACES Transform node takes in a 2D image, for instance a Loader node or the MediaIn1 pictured below. From the output, the node tree carries on by linking into a further 2D image-processing node or a Merge node.

### Controls Tab

Only the handful of primary controls required to carry out the ACES transform on the input live in the Controls tab. ACES Version Picks which release of ACES you would like to apply. Output Transform From this menu you settle on an ODT (Output Device Transform) that converts the image data into the color space of your exported timeline. Gamut Compress Type Here you decide which variety of ACES Gamut compression the node applies. Either choice can stop strongly saturated, monochromatic emitters (LEDs, neon signs, tail lights, etc.) from pushing past and clipping the gamut.

### Chromatic Adaptation [CrA]

### The Chromatic Adaptation node

### Chromatic Adaptation Node Introduction

A straightforward node that lets you accurately convert an image originally lit or handled under one particular color temperature into a different color temperature of your choosing. Such a conversion shifts how every color in the picture appears to human vision exactly as a fresh illuminant would, regardless of whether that illuminant is a light in the recorded environment or the color temperature of a screen the picture is viewed on. The node comes in handy for carrying out targeted color temperature conversions within color management workflows, or for establishing precise color temperature tweaks.

### Inputs

There are two inputs on the Chromatic Adaptation node, namely the input plus the effect mask. Input: The orange input carries the main 2D image used for the auto gain. Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. Wiring a mask here confines the change to only the pixels falling inside that mask. The effect mask gets applied once the tool itself has finished processing.

### Basic Node Setup

Much like numerous other 2D image-processing nodes, the Chromatic Adaptation node takes in a 2D image, for instance a Loader node or the MediaIn1 pictured below. From the output, the node tree carries on by linking into a further 2D image-processing node or a Merge node.

### Inspector

### ACES Transform controls

### Controls Tab

Only the primary controls required for tuning the Chromatic Adaptation parameters live in the Controls tab. Method The Method pop-up menu offers a range of distinct transform methods you can select, with CAT02 as the default. Every choice within the Method pop-up menu draws on separate measurement datasets to build individual CAT matrixes that steer the conversion. Consequently, each method emphasizes differing levels of precision across different groups of colors. As an illustration:

- CAT02 carries a non-linear element that corrects the tendency of very saturated blues to shift toward purple, a common shortcoming of competing methods. Across the broadest array of measured data sets it typically delivers the strongest result, and it performs best with emissive sources (displays) and dim viewing environments.
- Bradford Linear is another widely adopted method, though one where extremely saturated blues will shift toward purple over the course of the transform. It does a good job alike with emissive sources set in dim surroundings and with reflective sources (theater screens) placed in darkened ones.
- Von Kries ranks among the oldest methods still widely used, even if it too is one where extremely saturated blues shift toward purple over the transform. This method, along with every other one, is on hand whenever you must align with work produced in a separate image processing application.

NOTE: Keep in mind that each method on the list will reproduce neutral colors flawlessly; the sole distinctions concern the way varying bands of saturated color get transformed.

Source/Target Illuminant This conversion is governed via pop-up menus that establish the Illuminant Type for the source (usually whatever color temperature the camera was configured to) along with that of the target you intend to convert the picture into. Within either set of controls, you may select a Standard Illuminant from a list, dial in a Color Temperature with a slider, or supply CIE 1931 xy coordinate values. The conversion of the image is exceptionally accurate, since the picture first goes from the Timeline Color Space across to XYZ, after which it is converted to align with the LMS (long, medium, short) color space that emulates how the eye's cones respond to colors illuminated by various illuminants.

Current Color Space and Gamma The node likewise factors in the clip's present color space and gamma, both of which default to whatever the current timeline uses. Should you want to alter these settings, the Color Space and Gamma menus let you do that.

### Color Space Transform [CST]

### The Color Space Transform node

### Color Space Transform Node Introduction

A straightforward node that lets you carry out the same sort of color transforms LUTs perform, except rather than relying on lookup tables, this plugin applies the identical math that Resolve Color Management (RCM) uses so as to produce exceptionally clean color transforms free of clipping.

### Inputs

There are two inputs on the Color Space Transform node, namely the input plus the effect mask. Input: The orange input carries the main 2D image used for the auto gain. Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. Wiring a mask here confines the change to only the pixels falling inside that mask. The effect mask gets applied once the tool itself has finished processing.

### Basic Node Setup

Much like numerous other 2D image-processing nodes, the Color Space Transform node takes in a 2D image such as a Loader node or the MediaIn1 pictured below. From the output, the node tree carries on by linking into a further 2D image-processing node or a Merge node.

A Color Space Transform node applied to a MediaIn1 node

### Inspector

### Color Space Transform controls

### Controls Tab

Only the primary controls required to carry out the Color Space Transform on the input live in the Controls tab. Color Space Transform Surfaces four pop-up menus letting you assign an Input Colorspace, Input Gamma, Output Colorspace, and Output Gamma, so you can run governed transforms from the Input settings over to the Output settings entirely inside a node. The Swap button gives you a fast way to flip the color and gamma space conversion around. Tone Mapping Tone Mapping enables tone mapping to handle workflows where one color space has to be transformed into another carrying a far bigger or far smaller dynamic range, by automating a stretch or squeeze of image contrast in a manner that yields a pleasing outcome without clipping.

- None: This setting turns off Input DRT Tone Mapping. No tone mapping is applied at all to the Input to Timeline Color Space conversion, leaving a plain 1:1 mapping to the Timeline Color Space.
- Clip: Hard clips all out-of-bounds values.
- Simple: Relies on a plain curve to carry out this conversion, squeezing or stretching the

highlights and/or shadows belonging to the timeline dynamic range so they sit better inside the output dynamic range. Bear in mind the “Simple” choice spans roughly 5500 nits down to 100 nits, which means that converting an HDR source carrying beyond 5500 nits toward an SDR destination can still leave a degree of clipping in the highlights past 5500 nits.

- Luminance Mapping: Behaves like DaVinci, yet proves more precise once the Input Color Space of every piece of your media sits within one standards-based color space, for example Rec. 709 or Rec. 2020.
- DaVinci: This choice tone maps the transform with a gentle luminance roll-off through the shadows and highlights, plus managed desaturation of image values in the very brightest and darkest regions of the picture. The setting is especially handy for wide-gamut camera media and makes a solid choice when blending media originating from different cameras.
- Saturation Preserving: This choice carries a gentle luminance roll-off through the shadows and highlights, yet accomplishes it without desaturating dark shadows and bright highlights, making it an effective pick for colorists who prefer to drive color more aggressively. Still, because over-saturation in a picture's highlights can appear unnatural, two parameters are surfaced to supply a measure of user-adjustable automated desaturation.

Sat. Rolloff Start: Lets you assign a threshold, expressed in nits (cd/m2), where saturation begins rolling off in tandem with highlight luminance. Beginning of the rolloff. Sat. Rolloff Limit: Lets you assign a threshold, expressed in nits (cd/m2), at which the picture becomes wholly desaturated. End of the rolloff. Use Custom Max Input/Output: Ticking these boxes and nudging the slider underneath lets you state the lowest and highest luminance of the input picture in nits. Working these two sliders in combination, you decide which value drawn from the Input Gamma maps over to which value of the Output Gamma.

- Adaptation: Applied to make up for sizable shifts in the viewer's degree of visual adaptation between seeing a bright picture on an HDR display and seeing that very picture on an SDR display. For the majority of “average” pictures this setting performs best between 0–10. That said, when you're converting extremely bright pictures (a snow scene at noon, say), a higher value will surface more image detail inside the highlights.

Gamut Mapping Gamut Mapping Method handles workflows where one color space has to be transformed into another with a far bigger or far smaller gamut, by helping automate a stretch or squeeze of image saturation in a manner that yields a pleasing, naturalistic outcome without clipping.

- None: results in no Gamut mapping at all.
- Saturation Mapping: Switches on saturation mapping so the span of saturation values is fitted from the

Input Color Space and Gamma into the Output Color Space and Gamma. Doing so activates the Saturation Knee and Saturation Max. controls. The Saturation Knee slider establishes the picture level where saturation mapping kicks in. Beneath that level, nothing gets remapped. Every saturation value from that level upward gets remapped per the Saturation Max. slider. A value of 1.0 represents full saturation within the output color space currently chosen. The Saturation Max. slider establishes the fresh ceiling to which you intend to either lift or drop all saturation values sitting above the Saturation Knee setting. A value of 1.0 represents full saturation within the output color space currently chosen.

- Clip: Hard clips all out-of-gamut values.

NOTE: Although this node carries ACES settings, it performs transforms into the ACES color space colorimetrically, which isn't genuinely right for ACES workflows. For real ACES workflows, turn to the ACES Transform node, which relies on transforms laid out by the Academy.

Advanced From this drop-down menu the advanced features of the Color Space Transform node are surfaced.

- Apply Forward OOTF: Tick this box to shift the picture from scene referred color management to display referred.
- Apply Inverse OOTF: Tick this box to shift the picture from display referred color management to scene referred.
- Use White Point Adaptation: Applies a chromatic adaptation transform to take account of differing white points across color spaces.

Leave this box unticked when you simply wish to look at the input color space's white point unaltered within the output color space. As an example, wanting to bring a P3-D60 mastered clip into a P3-D65 timeline for reference. Tick this box to run the chromatic adaptation transform so the input white point is converted to align with the output color space's white point. As an example, wanting a P3-D60 mastered clip to intercut alongside other clips mastered within a P3-D65 timeline.

### Gamut Limiter [GML]

### The Gamut Limiter node

### Gamut Limiter Node Introduction

Lets you constrain the gamut down to a stated standard. Handy when the delivery color space is a wide gamut like Rec. 2020, yet the QC specification calls for restricting things to a tighter gamut like P3, so as to cap how much saturation the final output may contain. Since this is a limiting operation, any out of bounds values get hard clipped. Being a limiter, it ought to sit among the very last operations in any node tree so that useful image data isn't clipped away.

### Inputs

There are two inputs on the Gamut Limiter node, namely the input plus the effect mask. Input: The orange input carries the main 2D image used for the auto gain. Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. Wiring a mask here confines the change to only the pixels falling inside that mask. The effect mask gets applied once the tool itself has finished processing.

### Chromatic Aberration Removal [CAR]

### The Chromatic Aberration Removal node

### Chromatic Aberration Removal Node Introduction

A node that lets you hand-correct the faint color fringing produced by chromatic aberration within a lens. Show Estimated Fringes checkboxes for the RGB channels present an “alignment guide” that visually separates each kind of fringing against gray.

Effect Mask: The blue input takes a mask shape generated by polylines, simple primitive shapes, paint strokes, or bitmaps coming from other tools. ### Inspector

### Chromatic Aberration Removal controls

### Controls Tab

Only the primary controls required for tuning the Chromatic Aberration Removal parameters live in the Controls tab. Advanced Options Advanced Options supply extra parameters aimed at problem shots.

- Lens Center: Center X and Y parameters let you shift the lens center whenever you're handling a reframed and re-rendered shot.
- Stronger Correction: Reveals the spots of image features that look like fringing.

Estimation Options The Estimation Options exist purely to flag and pinpoint regions of fringing. They leave the picture's final output untouched. They turn available only once one of the Show Estimated Fringes boxes has been ticked inside the Aberration Correction section.

- R/C, G/P, B/Y Balance: These tools tune the incoming balance among their respective colors so hard-to-spot fringing becomes easier to identify.
- Brightness: Amplifies the fringe indicators shown whenever you switch on either of the Estimated Fringes checkboxes.

Aberration Correction These tools let you apply manual tweaks that fix aberration problems.

- R/C, G/P, B/Y Scale: Move these sliders to wipe out the fringing from their respective colors.
- R/C, G/P, B/Y Edge: Adjusts to make up for the variation in fringing caused by the curvature of

the lens' edges
